# 개발 기준과 진행 계획

## 승인 범위

로그인·금융 연동·외부 API 없이 사용하는 개인 가계부를 구현한다. 데스크톱과 태블릿을 우선 지원하고, 웹 화면과 계산 로직을 Android APK에서 재사용한다. 기본 통화는 원화이며 금액은 정수로 저장한다.

## 화면

- 메인: 총 자산, 월 수입·지출, 오늘 예산, 대표 계좌, 최근 지출.
- 돈 쓰기/벌기: 계좌·카테고리·날짜·감정 태그 입력.
- 내역 보기: 기간·구분·카테고리·감정 필터, 거래 수정·삭제.
- 지출 분석: 전월 동기간 비교, 카테고리별 상위 5개, 소비 속도, 낭비 지출.
- 내 계좌 모음: 등록, 잔액 조정, 대표 계좌, 보관과 복원.
- 고정비 스케줄러: 월별 예정 내역과 납부 처리.
- 설정: 가계부 이름, 월별 수입·저축 목표, JSON 백업·복원.

## 금액과 날짜 규칙

1. 월 변동비 예산 = 설정 월 수입 - 목표 저축액 - 월 고정비 합계.
2. 오늘 권장 예산 = (월 변동비 예산 - 어제까지의 변동 지출) / 오늘 포함 잔여 일수. 화면에는 원 단위로 내림한다.
3. 오늘 남은 예산 = 내림한 권장 예산 - 오늘 변동 지출. 음수는 초과 금액으로 안내한다.
4. 고정비 납부 거래는 지출 통계와 계좌에 반영하지만 변동비 지출에서는 제외한다.
5. 실제 가용 자산 = 전체 계좌 잔액 합계 - 이번 달 미납 고정비. 저축 목표와는 구분한다.
6. 거래 날짜는 기기 현지 날짜인 YYYY-MM-DD로 저장한다. 미래 거래 입력은 허용하지 않는다.
7. 전월 비교는 월초부터 같은 일자까지 비교한다. 전월에 해당 날짜가 없으면 전월 말일까지 사용한다. 과거 월 조회는 두 달 전체를 비교한다.
8. 비교 기준 지출이 0이면 증감률을 계산하지 않는다. 빈 데이터와 0원 예산은 명시적으로 안내한다.
9. 말일을 넘는 고정비 출금일은 해당 월 말일로 보정한다. 예정일만으로 출금하지 않는다.

## 데이터 모델

하나의 버전 있는 JSON 문서를 LocalStorage의 `household-book:v1` 키에 저장한다.

- `schemaVersion`, `revision`, `updatedAt`: 형식과 동시 편집 감지용 정보.
- `settings`: 가계부 이름, 대표 계좌 ID.
- `goals`: YYYY-MM별 월 수입과 목표 저축액. 새 월은 최근 이전 월의 목표를 이어받는다.
- `accounts`: 고유 ID, 이름, 시작 잔액, 보관 여부.
- `transactions`: ID, 계좌 ID, 현지 날짜, 유형, 금액, 내역, 카테고리, 감정, 고정비 월별 ID.
- `fixedExpenses`: 반복 고정비 원본, 시작 월, 활성 상태.
- `fixedMonths`: 월별 고정비 스냅샷. 과거의 금액과 납부 내역을 보존한다.

계좌 잔액은 시작 잔액과 거래를 합산하여 구한다. 거래 수정·삭제 때 따로 잔액을 갱신하지 않아 중복 반영을 방지한다. 잔액 직접 수정은 별도의 조정 거래로 기록하고 수입·지출 집계에서 제외한다. 연결 거래가 있는 계좌는 삭제 대신 보관한다.

저장은 검증한 전체 문서를 한 번의 `setItem`으로 반영한다. 저장 성공 후에만 화면 상태를 변경한다. 여러 탭 사이의 완전한 트랜잭션을 보장한다고 표현하지 않는다. revision 변경 시 재조회하게 하고 다른 탭 갱신을 안내한다. 저장 공간 부족·저장 차단·손상 데이터가 발견되면 원본을 덮어쓰지 않는다.

복원은 형식·자료형·참조·금액·날짜·중복 ID를 검증한 후 전체 교체한다. 사용자에게 교체 내용을 안내하고 확인을 받는다. 앱은 외부 스크립트·폰트·분석 도구를 사용하지 않는다. 웹과 APK는 별도 저장소를 사용하며 JSON 파일로 이동한다.

## 반응형 기준

- 데스크톱 1280~1920px: 고정 세로 메뉴, 넓은 본문, 다열 카드.
- 태블릿 가로 1024~1280px: 축소 세로 메뉴, 2~3열 카드, 입력 폼 2열.
- 태블릿 세로 768~1023px: 상단 메뉴 버튼과 접히는 세로 메뉴, 카드 1~2열.
- 더 작은 화면: 1열 배치. 표는 지정한 영역 안에서만 가로 스크롤한다.
- 터치 조작 영역 최소 44px, 키보드 포커스 표시, 모달 초점 이동과 복귀를 제공한다.

## 개발 순서와 검증

1. 요구사항과 데이터 모델을 정리한다.
2. 데스크톱·태블릿 반응형 화면과 메뉴를 구현한다.
3. 저장·계좌·거래 기능과 잔액 정확도를 검증한다.
4. 예산·고정비·통계와 날짜 경계를 검증한다.
5. JSON 백업·복원, 저장 실패, 오프라인 재실행을 검증한다.
6. Android에 로컬 웹 파일을 포함하고 앱 저장과 파일 입출력을 지원한다.
7. 전체 검사, 웹 배포 파일, APK, 사용 안내를 준비한다.

웹은 GitHub Pages의 HTTPS 경로에서 배포하며 서비스 워커 캐시가 준비된 후 오프라인 재실행을 지원한다. APK에는 파일을 포함하여 첫 실행도 오프라인으로 지원한다. 공개 배포의 성공 여부는 실제 배포 결과로 별도 보고한다.

## 후속 지시 반영

사용자가 기능과 화면을 직접 수동으로 검증한다. 자동 테스트·브라우저 자동 검증·에뮬레이터 검증은 추가로 실행하지 않는다. 개발과 실행 파일 생성, 사용 안내 작성은 계속 진행한다. 기존 테스트 코드는 보관한다.
